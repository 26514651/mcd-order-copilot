> 在麦当劳点单前，先看清这一顿的**蛋白、碳水、脂肪、热量**。
> 所有数字来自**麦当劳 MCP 官方接口实时获取** —— 仓库里一个数字都没有硬编码。

## 一句话

**给增肌、减脂、控碳水的人，一个「点单前 30 秒」就能用的营养速查。**

不是又一张静热热量表。菜单是**这家店此刻在售的**，数字是**刚刚取的**，套餐换了配餐会**实时重算**。

---

## 这是什么

很多人吃麦当劳的时候心里没数：这一顿到底多少蛋白、多少碳水、多少脂肪、多少热量？

网上的热量表要么来源不明，要么年份久远，同一款汉堡能查出三个不同的数字。

点单参谋做的是三件事：

1. **把数字摆出来** —— 每个餐品的 6 项参数（能量 / 蛋白 / 脂肪 / 碳水 / 钠 / 钙），一眼可见，不用点进二级页
2. **让数字是真的** —— 全部从麦当劳 MCP 官方接口实时取，随菜单和价格一起变
3. **让套餐也能算** —— 套餐不是一个死数字，换小食、换饮料，营养和价格一起重算

## 给谁用

| 用户 | 场景 | 原本的麻烦 | 用之后 |
|---|---|---|---|
| **增肌期** | 练完想吃点扎实的 | 不知道哪个组合蛋白够 | 按蛋白筛选，直接看达标项 |
| **减脂期** | 想吃但怕超 | 靠猜，吃完才后悔 | 先设今日剩余热量，再挑 |
| **控碳水** | 需要盯碳水总量 | 全靠记，容易漏 | 碳水一列直接排序 |
| **高蛋白** | 想多吃蛋白质 | 得一个个查 | 蛋白列排序，Top 项直接给 |
| **不知道自己该吃多少** | 新手 | 参数看不懂 | 选「增肌期 / 减脂期 / 增肌减脂期」，参考值自动配好 |

> ⚠️ 本项目**不面向**糖尿病、肾病、孕期、儿童、进食障碍及**食物过敏**人群。以上属于医疗或安全范畴，请咨询医生。我们**不提供**任何医疗建议。

## 快速开始

> 前置条件：需要一个麦当劳 MCP Token（免费申请：<https://open.mcd.cn/mcp>，手机号登录 → 控制台 → 激活）。

```bash
# 1. 拿到代码
git clone https://github.com/<your-name>/mcd-order-copilot.git
cd mcd-order-copilot

# 2. 把 Token 放进环境变量（不要写进任何文件）
export MCD_MCP_TOKEN="your_token_here"       # Windows: set MCD_MCP_TOKEN=...

# 3. 按 mcp-config.example.json 的格式，把 mcd-mcp 配到你使用的 MCP 客户端
```

**配好之后，你可以直接在 MCP 客户端里问：**

```
帮我看看巨无霸和板烧鸡腿堡的营养，我要增肌
```

**预期看到什么**：AI 会实时调用 `list-nutrition-foods` 取营养、`query-meals` 取这家店在售菜单，然后给出带具体数字的对比，而不是编一段话。

> 当前版本的交互界面（参数卡 / 详情面板）正在开发中，进度见下方「项目状态」。

## 它能做什么

| 能力 | 说明 | 用到的 MCP 工具 |
|---|---|---|
| 全量营养速查 | 160 条餐品的 6 项营养，含饮品、咖啡、甜品、早餐 | `list-nutrition-foods` |
| 门店在售菜单 | 绑定具体门店，取此刻真实在售的 86 项 / 13 分类 | `query-meals` |
| 套餐成分拆解 | 拆出套餐包含哪些单品、每个轮次可换什么 | `query-meal-detail` |
| 套餐营养加总 | 按选中成分求和，换配餐实时重算 | `query-meal-detail` + `list-nutrition-foods` |
| 特制项查询 | 显示可去掉的配料（如巨无霸酱），**不做热量差值估算** | `query-meal-detail` |
| 价格计算 | 按选购商品与优惠券计算金额 | `calculate-price` |
| 餐品图片 | 列表图 / 详情图，取自官方图片 CDN | `query-meals` |

> 标注「已实测调用」的工具均已完成实际调用验证；其余为设计中使用、待联调的接口。
> 完整状态见 **[MCP_INTEGRATION.md §2](./MCP_INTEGRATION.md)**，调用链路与业务价值见同文件 §3–§5。

## 真实性是怎么保证的

这个项目的核心原则只有一句：

> **数字永远是官方的，判断永远是标注过的。**

| 做法 | 说明 |
|---|---|
| **零硬编码** | 代码里没有任何一个营养数值。所有数字请求接口得到 |
| **标注来源与时间** | 界面上标出「数据来自 XX 餐厅 · 时间」 |
| **拿不到就说拿不到** | 部分新品官方暂无营养数据 → 显示「暂无官方数据」，**绝不估算** |
| **不做无依据的差值** | 官方不返回「去酱后少多少千卡」→ 因此**我们不说**，只列可去掉的配料清单 |
| **不覆盖医疗人群** | 没有过敏原数据 → 过敏人群绝不做推荐 |

## 已知限制（诚实版）

| # | 限制 | 说明 |
|---|---|---|
| 1 | **没有 GI 值** | 官方字段中无升糖指数。因此「控糖」实际只能做**碳水总量**控制，标签用「控碳水」，不做升糖承诺 |
| 2 | **没有配料级营养** | 拿不到「酱料单独多少千卡」，所以不提供「去酱省 X 千卡」这类数字 |
| 3 | **部分新品无营养数据** | 官方营养表暂未收录的新品，显示「暂无官方数据」 |
| 4 | **没有过敏原信息** | 官方字段不含过敏原，相关人群请以门店信息为准 |
| 5 | **单位口径** | 官方未标注每份 / 每 100g，本项目统一按**每份**展示并在界面注明 |

## 安全提示

- 本项目**不会记录或上传**你的 MCP Token。请通过环境变量注入，不要硬编码或提交到仓库。
- `mcp-config.example.json` 中**不含任何真实 Token**，只有 `${MCD_MCP_TOKEN}` 占位符。
- 涉及**真实下单、积分兑换、抽奖**的操作会改动你的真实账户数据，本项目当前**不调用任何写操作工具**。

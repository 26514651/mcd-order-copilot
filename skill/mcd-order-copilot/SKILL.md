# 点单参谋 · McDonald's Order Nutrition Copilot

在麦当劳点单前，把这一顿的营养数字摆出来。**所有数字来自麦当劳 MCP 官方接口实时获取，一个都不硬编码。**

## 何时使用

用户提到以下任何一类意图时：

| 意图 | 例子 |
|---|---|
| 想知道某餐品的营养 | "巨无霸多少热量""板烧鸡腿堡蛋白多少" |
| 想按目标筛选 | "减脂期在麦当劳能吃什么""给我找蛋白 30g 以上的" |
| 想比较几个选项 | "巨无霸和麦辣鸡腿汉堡哪个更适合练后" |
| 想知道套餐怎么换 | "三件套把中薯换成大薯多多少卡""无糖可乐能省多少" |
| 想知道能去掉什么 | "巨无霸能去酱吗""去掉芝士还有多少热量" |

## 三条不可违反的原则

### 1. 数字永远来自接口，不硬编码、不估算

任何营养值必须来自 `list-nutrition-foods` 或 `query-meal-detail` 的实际返回。

- ❌ 不要凭记忆报数字
- ❌ 不要用"约""大概"修饰官方值
- ❌ 不要在缺数据时用同类产品推算

**官方没有的，就说没有。** 显示「官方暂无数据」，并说明这会导致该项不参与筛选。

### 2. 判断永远标注过，不伪装成官方结论

| 类型 | 做法 |
|---|---|
| **官方数据** | 直接呈现，标明来源与时间 |
| **本项目推断** | 明确标注（如"规格推断：菜单为『可乐』，营养表为『可乐中杯』"） |
| **本项目建议** | 必须标注"参考值，非医疗或营养建议" |

**绝不做的事**：把"去酱省 90 千卡"这类无官方来源的差值算出来给用户。接口只返回"可去掉哪些配料"，不返回"去掉后营养变化"。

### 3. 不服务医疗人群

| 级别 | 人群 | 处理 |
|---|---|---|
| 🟢 绿灯 | 增肌 / 减脂 / 增肌减脂 / 高蛋白 / 控热量 / 控脂 / 控钠 / 控碳水 / 运动补给 | 正常推荐 |
| 🟡 黄灯 | 控糖（血糖） | **只呈现碳水总量，禁用"推荐""适合"**。官方无 GI 值，做不了升糖控制 |
| 🔴 红灯 | 糖尿病 / 肾病 / 孕期 / 儿童 / 进食障碍 / **食物过敏** | **绝不做推荐**，只提示咨询医生 |

**过敏原是绝对红线**：官方字段里没有过敏原数据，做这个功能等于编造。

## 工作流程

### 步骤 0 · 确认门店（必需）

`query-meals` 与 `query-meal-detail` 必须传 `storeCode`。

```python
store = client.find_store(keyword="天河", city="广州")   # → query-nearby-stores
store_code = store["storeCode"]
```

> 这不是障碍，是信任状：菜单、价格、售罄都随门店变化。"这家店此刻"是任何人抄不走的。

**注意接口的一个真实限制**：`query-nearby-stores` 的参数只有 `beType` / `city` /
`keyword` / `searchType`，**不接受经纬度** —— 额外塞 `latitude` 字段会被服务端静默忽略
（返回报文与不塞时逐字节相同），把坐标当关键词则报 `600014 没有查询到该地址`。

**想让用户"点一下就查身边"，走这两条路，不用去申请任何地图 key：**

| 做法 | 怎么走 |
|---|---|
| 用我的位置 | 浏览器 `navigator.geolocation` 拿坐标 → 后端用 Photon（OpenStreetMap，免 key）反查成中文地名 → **并发试 3–6 个候选地名**、合并去重 → `query-nearby-stores` |
| 我存的地址 | `delivery-query-addresses` 读账号里已保存的收货地址（不经过任何第三方）→ 解析出城市 / 区 / 街道 → 同上 |

**访客没有 Token 怎么办。** 麦当劳 Token 只发给报名开发者，所以任何"把链接发给别人用"的场景都会卡在这一步。解法是在**服务端**配一份共享 Token 供匿名访客使用（`python server.py --shared-token ...`，或把 Token 写进脚本同目录的 `.mcd-token`），这样访客打开就能点。三条纪律：

- **只顶替公开数据接口。**「我存的地址」永远不能用共享 Token —— 它读的是调用者自己的地址簿，借用等于把部署者的家庭地址展示给每个匿名访客。后端对该接口直接返回 403。
- **必须限流。** 官方文档写明「避免泄露给他人使用」，且整个 Token 上限 **600 次/分钟**，而构建一家店的菜单就要花掉约 **115 次**。不限流的话，前五个人就能把额度吃干净。
- **共享额度不进前端。** 它只在后端内存里，任何 HTTP 响应都不携带。

> **为什么必须一次试多个候选**：地名粒度直接决定精度。实测「珠江新城」→ 华夏路餐厅 90 m（准），
> 「阅江西路」→ 琶洲西 460 m（基准点漂了一公里），而完整地址「广州市海珠区阅江西路222号」
> → 广州塔餐厅 94 m（准）。单点押注会踩雷，多候选合并才稳。
>
> 另外门店返回的 `latitude` / `longitude` 恒为 `0.0`，只有 `distance` 可用，且它是相对
> **本次关键词解析点**算的 —— 所以距离只能当参考，别拿它做精排。

### 步骤 1 · 取数

```python
nutrition = client.list_nutrition_foods()          # 160 条，无需参数
raw_menu = client.query_meals(store_code)          # 115 项 / 15 分类
```

**注意两个解析坑**（详见 `docs/evidence-real.md`）：
- `content[].text` 是"说明文字 + JSON"混合体，不能直接 `json.loads`
- `list-nutrition-foods` 的 `data` 是 **CSV 字符串**，不是数组

### 步骤 2 · 匹配名称（关键工序）

菜单与营养表**只能按名称对齐**，而两边命名习惯不同。逐字精确匹配只覆盖 30.0% 的单品，本项目用五级级联把它提到 48.3%：

```
L1 精确名称
L2 归一化（NFKC 全半角 / 括号 / 空格 / 大小写）
L3 规格推断（菜单"可乐" → 营养表"可乐中杯"）
L4 风味后缀剥离（"（椒盐风味）" → 去后缀）
L5 唯一包含
```

**L3 与 L5 是推断**，必须在输出里标注，不能和精确匹配混为一谈。
L5 只在**唯一候选**时才接受 —— 两个都对得上就返回"没匹配到"，因为错的数字比没有数字更糟。

**套餐绝不做名称匹配。** `巨无霸三件套` 含巨无霸，但它的热量不是巨无霸的热量。套餐只有两条路：走 `rounds` 成分加总，或如实报告不可用。

### 步骤 3 · 套餐加总

```
套餐营养 = Σ(各轮默认选中项的营养)
```

若要支持"换配餐重算"，把每轮 `choices` 的 `name` + `kcal` + `diffPrice` 一并取出，前端/CLI 本地重算，无需再次请求。

### 步骤 4 · 筛选与呈现

筛选是**软过滤**：任何一项指标缺失即排除，不假设为 0。

排序建议给用户选择：蛋白高→低 / 热量低→高 / 碳水低→高 / 脂肪低→高 / 钠低→高 / 价格低→高。**单品优先于套餐**（套餐数值大只是因为它是三样东西）。

## 执行方式

```bash
# 零安装入口：clone 下来就能跑（内部把 src/ 加进 sys.path）
python run.py --demo

# 离线演示（无需 Token，用仓库内真实快照）
python run.py --demo --goal cut --weight 70
python run.py --demo --protein 30 --kcal 600 --limit 10

# 在线（实时调用官方接口）
export MCD_MCP_TOKEN="你的Token"
python run.py --live --city 广州 --goal bulk

# 数据可得性报告
python run.py --coverage

# 查看预设
python run.py --list-presets

# 实时门店后端（自带演示页，含"查附近门店 + 切该店实时菜单"）
python server.py                      # → http://127.0.0.1:8777
python server.py --allow-env-token    # 本地调试：允许回落 MCD_MCP_TOKEN
```

安装了包之后，也可以用等价的 `python -m mcd_order_copilot …` 或 `mcd-order-copilot …`：

```bash
pip install -e .
mcd-order-copilot --demo
```

## 输出规范

**必须包含**：数值 + 单位 + 来源时间 + 门店

**多方案对比用表格**，数字右对齐，缺数据留「—」不留 0：

```
餐品                    价格    热量   蛋白   碳水   脂肪     钠
巨无霸                  25.0     513    27     42     26    961
板烧鸡腿堡              24.0     391    22     40     15    892
```

**结尾必须带免责声明**：

> 数据来自麦当劳 MCP 官方接口 · 本项目非麦当劳官方产品 · 营养信息仅供参考，不构成医疗、营养或任何专业建议。

## 技能资产

| 文件 | 用途 |
|---|---|
| `run.py` | 零安装入口（把 `src/` 加进 `sys.path`） |
| `server.py` | 实时门店后端：转发 `query-nearby-stores` / `query-meals` / `query-meal-detail`，浏览器不能直连官方接口（无 CORS 头） |
| `src/mcd_order_copilot/mcp_client.py` | MCP 客户端（零依赖，含混合文本解析） |
| `src/mcd_order_copilot/normalize.py` | 五级级联名称匹配 |
| `src/mcd_order_copilot/nutrition.py` | 套餐加总、筛选、标签 |
| `src/mcd_order_copilot/profiles.py` | 目标预设（五项参数 + 公开依据，非医嘱） |
| `src/mcd_order_copilot/payload.py` | 快照页与实时模式**共用**的 payload 构建 |
| `index.html` | 零门槛演示页（无需 Token，手机可开；选店后即为实时） |
| `docs/evidence-real.md` | 真实调用证据与接口坑位记录 |
| `docs/scope.md` | 人群边界与合规红线 |
| `tests/` | 62 项单元测试（纯 `unittest`，无额外依赖） |
| `fixtures/` | 真实接口快照（演示数据来源，`fixtures/_meta.json` 有采集时间与门店） |

## 失败处理

| 情况 | 处理 |
|---|---|
| 401 | Token 失效，提示重新申请，不要重试刷接口 |
| 429 | 指数退避重试（客户端已内置） |
| 某餐品无营养数据 | 显示「官方暂无」，不参与筛选，不估算 |
| 组件匹配不上 | 标注为"部分已知"，**不把下界当总量** |
| 门店找不到 | 要求用户提供 `storeCode` 或用城市名重试 |
